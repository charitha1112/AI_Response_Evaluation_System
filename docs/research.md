Research and Technical Understanding

1. Overview

Artificial Intelligence tools and Large Language Models (LLMs) are widely used to generate answers, explain concepts and provide information. Although these systems can produce meaningful responses, their outputs are not always accurate or reliable. Sometimes, an answer may be irrelevant, incomplete or contain information that cannot be supported by reliable sources.

The proposed AI Response Evaluation System aims to address this problem by evaluating AI-generated responses using multiple parameters. The initial research focuses on understanding existing evaluation techniques, hallucination detection, RAG architecture and the tools required to develop the system.

2. Research on LLM Evaluation Techniques

LLM evaluation is the process of examining the quality of responses generated by large language models. A response should not be judged only by how well it is written; its actual content and relevance also need to be considered.

For this project, we identified four major evaluation dimensions:

Relevance: Determines whether the generated response properly addresses the user's question.

Accuracy: Checks whether the information provided in the response is factually correct.

Completeness: Examines whether the response covers the important information required to answer the question.

Hallucination Detection: Identifies claims or statements that are unsupported by the available reference information.

Faithfulness is also considered when checking whether a response is consistent with its supporting sources.

These dimensions will be used as the basis for designing the evaluation agents.

3. Hallucination Detection Methods

Hallucination is one of the important challenges in LLM-based applications. It occurs when a model generates information that appears convincing but is incorrect or unsupported by available evidence.

During the research, we studied different approaches to identifying hallucinations:

- Comparing generated answers with trusted reference answers.
- Verifying statements against supporting documents.
- Checking whether the response is consistent with retrieved information.
- Using model-based evaluation to examine unsupported claims.

These approaches will help us design a mechanism to identify potentially unreliable information in AI-generated responses.

4. Study of Retrieval-Augmented Generation (RAG)

Retrieval-Augmented Generation (RAG) is an approach that combines information retrieval with language models. It allows a system to retrieve relevant information from an external knowledge source and use it as supporting context.

The basic RAG process includes:

1. Collecting and preparing reference documents.
2. Converting the text into embeddings.
3. Storing the embeddings in a vector database.
4. Retrieving relevant information based on a user's query.
5. Using the retrieved information for further processing.

In our project, the RAG approach will be used to retrieve relevant reference information that can support the evaluation of AI-generated responses.

5. Embeddings and Vector Database

To retrieve information based on meaning, rather than depending only on exact keyword matching, we studied text embeddings and vector search.

Embeddings represent text in numerical form so that semantically similar content can be identified. A vector database stores these representations and allows the system to search for relevant information efficiently.

For the proposed system, Sentence Transformers will be explored for generating embeddings, while ChromaDB will be used as the planned vector storage solution.

6. LLM-as-a-Judge Approach

LLM-as-a-Judge is an evaluation technique in which a language model is used to assess the quality of responses generated by another model.

The judging model examines the response using predefined evaluation criteria and can assign scores based on the given instructions.

We studied this approach to understand how individual evaluation parameters can be assessed. It will be considered while developing the different evaluation agents in our system.

7. Study of Existing Evaluation Frameworks

As part of the research, we explored existing frameworks that are commonly used to evaluate LLM applications.

RAGAS: RAGAS is a framework designed to evaluate Retrieval-Augmented Generation systems. It provides evaluation metrics for examining aspects such as faithfulness, answer relevance and retrieval quality.

TruLens: TruLens provides tools for evaluating and monitoring applications built using large language models. It helps assess the quality and reliability of LLM-based applications.

Studying these frameworks provides a useful reference for selecting evaluation methods and designing our own evaluation workflow.

8. Reference Dataset Study

A reference knowledge base is an important part of the proposed system. We identified two publicly available datasets for the initial development.

TruthfulQA

TruthfulQA is a question-answering dataset designed to test whether language models provide truthful answers. It will be useful for studying factual reliability and identifying misleading responses.

SQuAD (Stanford Question Answering Dataset)

SQuAD contains questions, answers and supporting passages from source documents. It provides useful reference information for question-answering and context-based evaluation.

Both datasets are planned to be processed and organized before being added to the knowledge base.

10. Proposed System Development Approach

Based on the concepts and technologies studied, the system is planned to be developed using separate modules.

The input module will accept a question, an AI-generated response and an optional reference answer or source document. The backend will process the submitted information and pass it to the evaluation orchestrator.

The orchestrator will coordinate different evaluation agents. Each agent will focus on a particular dimension, such as relevance, accuracy, hallucination detection or completeness.

The reference knowledge base will provide supporting information through semantic retrieval. Finally, the evaluation results will be combined to generate an overall score and a final verdict.

This modular approach will make the system easier to develop, test and improve.

11. Research Outcome

The research carried out in this milestone provided an understanding of the major challenges involved in evaluating AI-generated responses. It also helped identify suitable evaluation techniques, existing frameworks, reference datasets and development technologies.

The findings from this milestone will serve as the foundation for the next stages of the project, particularly system architecture design, input module development and reference knowledge base implementation.
